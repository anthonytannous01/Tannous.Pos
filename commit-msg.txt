refactor(printing): consolidate to a single ESC/POS path — Step 114

Merged three parallel receipt implementations into one core/printing package.
Deleted SystemPrintPrinter, Printer.kt, ReceiptFormatter, PrintingManager,
ReceiptPrintManager, PrintingModule, core/ui/ReceiptPreview.kt, and the whole
feature:printing module with its nav route and Settings card — that screen
printed hardcoded sample data through the dead Android Print Framework path.
Moved PrinterService from feature/settings to core/printing; feature:sell no
longer depends on feature:settings.
Split rendering from transport: ReceiptRenderer produces layout-independent
rows serialized as either ESC/POS markup or plain text, with no Android or
printer dependencies, so receipt layout is unit-testable on the JVM.
Collapsed the two duplicate PrintResult types into one.
Repointed Share Receipt at the same server ReceiptDto the printer uses, so
shared text matches the paper exactly (previously omitted VAT, stamp duty and
the LBP total); share failures now surface in a snackbar instead of silently.
Receipts are English-only by decision — thermal printers cannot shape Arabic,
and the bitmap-rendering workaround was removed. App UI stays bilingual.

fix: 58mm paper width now works. Column placement is delegated to the printer's
  [L]/[R] parser instead of hardcoded 48-char padding, separator rules are
  generated at the configured width, and long item names truncate rather than
  colliding with the price column.
fix: VAT rate is derived from the receipt's own subtotal and tax instead of
  current settings. Prevents "VAT (0%)" printed against a non-zero amount, and
  stops a reprint showing a new rate against an old amount.
fix: the double-width shop name falls back to normal width when it cannot fit
  the paper (over 16 characters on 58mm), restoring centring.
fix: BluetoothAdapter.getDefaultAdapter() replaced with BluetoothManager on
  API 31+, matching what the settings UI already did.
chore: escpos dependency moved from a hardcoded version string into
  libs.versions.toml.

Added ReceiptRendererTest — the first unit tests in the mobile project. 12 cases
covering 58mm/80mm layout, rule widths, truncation, markup injection, the derived
tax rate, and the double-width fallback.
Added scripts/fake-printer.ps1 — a TCP 9100 listener that captures and renders
ESC/POS output, so receipt layout can be verified without buying a printer.

Retired the Cursor prompt-relay workflow: .cursorrules and CURSOR_RULES.md
consolidated into ARCHITECTURE_RULES.md (architecture contract preserved intact,
including the EF migration and git push rules), cursor_prompts/ deleted,
CURSOR_SQUARE_PHASE_BRIEFING.md renamed CODEBASE_BRIEFING.md, governance docs
repointed. Historical Cursor references in IMPROVEMENT_REPORT.md left intact as
changelog. PRINTING.md rewritten to describe the real system. TODO.md updated to
record that Arabic receipts are a decision, not an omission.

deviations: feature:printing deleted rather than rewired, and Share Receipt made
  network-dependent to match print — both agreed before implementation.
validation: :core:testDebugUnitTest green; 58mm and 80mm test prints captured and
  verified byte-level through fake-printer.ps1; real order print, Share Receipt
  (online and offline) and Settings navigation confirmed on device.
